1The problem & the proposed approach

Today the model admits sectors with either perfectly-elastic supply (e.g. unpaid care, priced at 0 to families) or finitely-elastic supply (the three paid sectors, which clear through the equilibrium solver). We want to add public provision — a 4K/3K-style program like New York City's — capturing the fact that public slots are capacity-constrained and administratively priced.

The proposed sketch:

  • Three new per-sector policy parameters: (a) number of public slots, (b) price paid to providers per slot, (c) out-of-pocket (OOP) cost to families per slot (often free; possibly means-tested).
  • First compute each family's choice probabilities assuming they can get a public slot.
  • If demand exceeds the number of slots, randomly assign children to slots, then recompute choice probabilities for the remaining children at market prices.

The core instinct is sound and maps onto the existing structure better than one might expect. Below: the constraint that dictates the design, the cleanest mapping, one reframing the plan needs, a checklist of substantive gaps, and the alternatives worth weighing.

2The binding constraint: a fixed, calibrated choice set

"Don't touch calibration" dictates almost everything. The α (preference heterogeneity) matrices are calibrated as n × (K−1) over a fixed choice set (45 columns for c1, 675 for c2plus). Choice probabilities are p = exp(α + V) / Z, with α backed out at calibration so observed/imputed choices are reproduced exactly.

Consequence

You cannot add a genuinely new "public" alternative to the catalog — a new column needs its own α, which means re-calibrating. Public provision must therefore be expressed as a price/cost transformation of an alternative that already exists, not as a new alternative.

This is workable, because the three parameters (slots, provider price, OOP cost) are a price-and-quantity intervention. The only real question is which existing alternative public care "is."

3Recommended mapping: the perfectly-elastic free sector, made explicit

Consider how the model already treats Unpaid Center-Based (sector 1):

  • Its price to families is fixed at 0 — the optimizer only solves P[2:4] (INITIAL_PRICES <- c(0,1,1,1)).
  • It still consumes labor: compute_supply_residuals() builds L_by_sector <- L_req * Qd over all four market sectors, and wages are w = w0 · (L/L0)^(1/e). So free-center demand already draws on the shared teacher pool and already pushes wages up.
  • Its supply participation constraint is simply not enforced: delta_gap_paid <- delta_gap[2:4]. Providers nominally "receive 0," cost is positive, and the model just doesn't target their residual. That is "perfectly elastic supply at price 0" — an implicit, uncapped, fully-subsidized sector.

Recommendation

Treat public provision as a capacity-capped, government-funded version of the free center sector — finite capacity (a), a real provider payment (b), and an OOP price (c) — rather than inventing a new alternative. Public 3K/4K is essentially the existing free-center sector made honest about its capacity and its cost.

Why this fits:

  • Zero change to the choice set or α.
  • Labor-market crowd-out onto private providers is already partly wired in — public demand flows into L, raising w, raising private unit costs and prices. You'd add only the provider payment (b) and the cap.
  • The "free to families" preference is already calibrated into that column.

The cost: public care becomes a perfect preference-substitute for whatever you map it onto (no distinct "public vs. private" taste). If you need that distinction, see option C in §6.

4The one reframing that matters: ration in expectation, lottery afterward

Problem with literal random assignment

Step 3 ("randomly assign children to slots") will break the equilibrium solver if taken literally. L-BFGS-B evaluates demand Qd(P) dozens of times and assumes a deterministic, roughly smooth objective. Random draws inside that loop make the objective jitter and it won't converge.

The model already has the exact pattern needed: smooth softmax for equilibrium, discrete random draws after (the existing Gumbel-ε expansion → argmax collapse). Public rationing should follow the same two-stage split:

Stage 1 — inside the equilibrium solve (smooth)

Compute each family's probability of wanting a public slot, p_i(public); aggregate to expected slot demand; apply an access probability:

D = Σ w_i · p_i(public) π = min(1, capacity / D)

Families face an expected budget set: public OOP price c with probability π, market price with probability 1 − π. This is deterministic given D, so the solver stays smooth. Rationed-out demand spills into the market sectors automatically, and private prices fall accordingly — a genuine spillover benefit even for non-recipients.

Stage 2 — in the post-equilibrium Gumbel / discrete step

Run the actual lottery: draw which children get the a slots, fix their access, let the rest face market prices, then perform the existing argmax collapse.

Why this is the same idea, relocated

This is the proposed plan with rationing folded into the smooth demand the way Gumbel shocks already are. It is also the standard "price-controlled good with excess demand clears on an access/queue probability" equilibrium — so the instinct is correct; it just needs to live in the right stage.

One wrinkle: π = min(1, capacity/D) has a kink at D = capacity. L-BFGS-B usually tolerates it; if convergence suffers, smooth it (a soft/congestion-price version of π — see option D).

5What the plan underweights (checklist)

5.1 — Labor-market crowd-out is the substantive heart of this

NYC's 3K expansion bid up early-ed wages and pulled staff out of private centers. The single most important decision is: does the public program pay the market wage w, or does its administered provider price (b) imply a wage that differs from the private market? If public pays above market, it pulls labor and raises w for everyone, raising private prices — a cost channel that can dwarf the mechanical transfer. If you map public onto sector 1, the quantity side is already in L; you'd decide whether (b) feeds the wage equation or sits outside it. Make this an explicit switch: partial-equilibrium "separate labor pool" vs. full-GE "competes for the same teachers."

5.2 — Slots are children × an hours bundle, and pre-K hours don't map cleanly

Capacity is in slots; the model thinks in annual hours (ft = 40×50, pt = 10×50). Public pre-K is typically a school-day/school-year schedule (~6.5 hrs, ~40 weeks) — neither ft nor pt. You must pick which hours bundle a slot corresponds to, and reckon with wraparound care: a family using public AM may still buy private PM care, which the one-arrangement-per-child structure can't represent without treating it as its own bundle.

5.3 — Per-child rationing in 2+ child families

A c2plus family might win one slot but not two, giving asymmetric per-child budget sets. The per-child cost matrices (child1_cost_matrix, child2_cost_matrix) already allow overriding one child's price while the other faces market prices — but the lottery and the recompute must be per child, not per family.

5.4 — A new fiscal line, plus interactions

Public cost = slots_used × (b − c) — a channel that doesn't exist today (current fiscal = demand + supply + employer subsidies + CDCTC − tax revenue). The 3d accumulation layer is structured to add a line. Two interaction traps:

  • A free slot should zero out CDCTC and demand subsidies for that choice — order the public OOP override before the subsidy/CDCTC stage in compute_policy_components(), and the existing pipeline handles the rest.
  • Much of the spending is an inframarginal transfer to families already buying center care (fiscal cost, distributional/poverty gain, little behavioral change), while the policy-relevant margin is families switching from parental/informal care. The logit plus the existing mechanical/behavioral decomposition captures this split for free — a real strength of doing it this way.

5.5 — Take-up will be overstated

A free, high-quality option in a logit pulls a lot of families. Real take-up is throttled by information, application hassle, and schedule mismatch that a money price c doesn't capture. Consider a take-up parameter or an additive "hassle cost" on the public option — there is precedent in the takeup parameter of the ARPA CDCTC policy.

5.6 — The rationing rule isn't necessarily random

NYC uses geographic/sibling/income priorities, and a means-tested c changes who applies. Random-among-applicants is a fine default (and is what a pure lottery does), but make the rationing rule a configurable parameter (random / income-prioritized / etc.) rather than hard-coding random.

5.7 — Baseline anchoring

If you reinterpret an existing free-center column as "public," the baseline capacity must reproduce currently-observed free-center usage, so the counterfactual is cleanly "added slots" rather than "discovering" slots that were already there.

6Alternative representations

A — Price override on an existing sector (the original plan, refined)

Public = a subset of families face OOP c on a center choice, provider gets b, rationed via expected-π then lottery.

Minimal calibration impact; public is a preference-clone of the host sector.

B — Capacity-capped free sector (reinterpret Unpaid Center-Based) · recommended default

Treat the existing free-center column as the public sector; add a capacity cap and a provider payment.

Best fit to the existing structure and labor market; requires baseline re-anchoring.

C — New column with a borrowed α

If public genuinely needs distinct preferences (e.g. a quality premium over private), add a public column at simulation time with α set from a comparable sector ± an assumed quality shifter.

Bends "no calibration change" slightly — you assert an α rather than estimate one — but it's the only way to get distinct public preferences without re-running calibration.

D — Congestion / shadow-price equilibrium

Mathematically equivalent to A/B, but solve for an implicit access price that clears demand = capacity.

Smoother for the optimizer than the min() kink.

7Decisions that drive the design

Three choices determine essentially everything downstream:

DecisionOptions
Host alternative Reinterpret the free-center sector (B), override a paid center sector (A), or borrow an α for a new column (C)?
Labor-market scope Does public hiring compete for the same teachers and move w (full GE), or draw from a separate pool (partial)? The biggest substantive call.
Slot lever Is capacity a purely exogenous, or do you also want a supply-side phase-in (you can't build classrooms instantly — phase_in_years already exists in the runscript)?

Once these three are settled, the implementation is reasonably localized: a public-price override and the expected-rationing step slot into compute_policy_components() / run_scenario(), the actual lottery rides on the existing Gumbel/discrete stage, and a new fiscal/accumulation line goes into 3d.
